# hpmsdkctl MCP Server

This server exposes local HPM SDK tooling through stdio MCP.

Use `config.check` before generating, compiling, flashing, or starting GDB. Configure using `config.init` with `sdk_env`, or explicit `hpm_sdk`, `cmake`, `ninja`, `python`, `toolchain` and optionally `openocd` paths. The modes are mutually exclusive. SDK Env import saves resolved paths; build options may also read the saved `sdk_env/cmd_params.yaml` for build-type definitions. Runtime commands use `config.json`. `HPMSDKCTL_CONFIG` overrides the stable per-user config path. Missing configuration loads as empty data without creating files. Initialization validates configured tool versions before saving. Set `hpm_sdk` and keep `env.HPM_SDK_BASE` synchronized. Read values with `config.get`, update them with `config.set`, and clear them with `config.unset` using `{"key": "tools.openocd"}` or a supported alias. Unset saves the updated configuration without running tool versions; clearing `hpm_sdk` also removes `env.HPM_SDK_BASE`. Use `config.list` to inspect all settings.

Query `build.list_options` with `sample` OR `app_dir` first. Select `board`, `hpm_build_type` and `cmake_build_type`. Generate with exactly one source and either `board` OR `custom_board`. A custom board contains `CMakeLists.txt` and `<name>.yaml` with `board.soc`. `custom_gcc_linker_file` optionally supplies a linker script. Default build directory: `<app_dir>/<board>_<hpm_build_type>_<cmake_build_type>`. `build.compile` requires a generated `build_dir` containing `build.ninja`.

Every tool returns `structuredContent` with `ok` describing whether the operation succeeded. On business failure, read `error` and `isError: true`. Discovery failures return null candidate lists; failed build discovery also returns `app_dir: null`. `build.generate`, `build.compile`, `openocd.flash`, `openocd.start_gdb_server` and `project.localize_sdk` also return `exit_code`, `stdout`, `stderr` and available directory context. `exit_code: null` means no process result was available, such as a validation, startup or cancellation failure. Captured stdout followed by stderr remains available as readable text. Do not write logs to protocol stdout.

Call `openocd.list_configs` with `board` and optionally `app` (sample path or app directory) to discover probes, socs, boards and default selections. Empty defaults require selection from available lists. app dependencies determine single/dual-core selection. `openocd.flash` requires `probe`, `soc`, `board` and `file`. Config names or `.cfg` paths are accepted. `address` accepts a decimal or hexadecimal integer. It is required for BIN firmware, optional for other formats, and is never inferred. `openocd.start_gdb_server` requires `probe`, `soc` and `board`, and runs until stopped/cancelled.

`project.localize_sdk` runs `ninja localize_sdk`. If `CMakeLists.txt.localized.bak` already exists, call `project.unlocalize_sdk` first. It takes `localized_dir`, preserves the current `CMakeLists.txt` as `CMakeLists.txt.unlocalized.bak`, and restores the localized backup.

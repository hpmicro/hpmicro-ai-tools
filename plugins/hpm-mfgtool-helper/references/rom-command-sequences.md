# ROM 命令序列

本参考仅描述 `hpm-mfg-tool-ctl` 当前已经封装的能力。镜像创建、镜像签名/加密和量产包
导出虽然由底层 CMD 支持，但当前 MCP 未暴露对应工具；遇到此类请求时说明能力缺口，不直接
执行 CMD 或拼接 shell 命令。

## Memory ID

| `memoryId` | 存储器   | 读/写 | 校验 | 配置 | 擦除 |
| ---------- | -------- | ----- | ---- | ---- | ---- |
| `0`        | ILM      | 是    | 是   | 否   | 否   |
| `1`        | DLM      | 是    | 是   | 否   | 否   |
| `0x10000`  | XPI0 NOR | 是    | 是   | 是   | 是   |
| `0x10001`  | XPI1 NOR | 是    | 是   | 是   | 是   |
| `0x20000`  | OTP      | 是    | 否   | 否   | 否   |
| `0x30000`  | SDXC0    | 是    | 是   | 是   | 是   |
| `0x30001`  | SDXC1    | 是    | 是   | 是   | 是   |

“读/写”表示 MCP schema 允许相应操作；具体设备、ROM 和 CMD 仍可能施加更严格限制。
OTP 每次只能读取一个 4 字节 word。连续读取时，每次 `rom.read_memory` 固定使用
`length=4`，起始地址必须 4 字节对齐，后续地址按 `+4` 递增；任一分块失败即停止。
OTP 写入属于一次性编程，执行失败时也不自动重试。

## 外部存储器参数

XPI NOR 和 SDXC/eMMC 在读、写、校验或擦除前需要运行时配置。配置字以及目标
`memoryId` 必须来自用户或对应 SoC 用户手册；这些值与 SoC 和存储器相关，不从示例推断。

XPI NOR 未指定其他有效暂存位置时，使用官方命令行示例的 ILM `memoryId=0`、
`address=0x200`。把配置字写到 `0x200` 后，`rom.config_memory.address` 必须继续使用
同一个 `0x200`。不得默认使用 `0x0`；该地址可能被 ROM 以状态 18 拒绝。若用户或 SoC
文档明确给出其他暂存位置，则两步统一使用该位置；失败后停止，不扫描或猜测其他 RAM 地址。
eMMC/SDXC 的暂存 RAM 类型和地址仍需由用户或对应文档确认。

XPI NOR 使用字节地址；SDXC/eMMC 的传输 `address` 使用扇区索引，但 `length` 仍使用
字节数。`rom.config_memory.address` 始终是配置字在设备 RAM 中的地址，不是烧写地址或
扇区索引。

启动镜像的烧写地址来自镜像信息或用户输入；当前 MCP 不解析镜像头，因此不得自动猜测。
eMMC 输入文件必须已经包含设备需要的固件容器头，且配置格式与 XPI NOR 不同。

## 失败边界

每个调用后检查结构化结果中的 `success`、`exitCode` 和 `timedOut`。任一步失败即停止
序列；日志只用于诊断。报告已完成步骤、失败步骤以及未执行步骤。
